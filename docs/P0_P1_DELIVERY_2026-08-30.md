# AgentTrust v0.5：P0/P1 实现、验证与商用差距

> **历史快照（2026-08-30）**：本文记录 v1.0.0 之前的一轮交付，测试数量和剩余风险仅代表当时状态。当前证据见 [Portfolio Evidence](PORTFOLIO_EVIDENCE.md)。

更新：2026-08-30。本文是当前实现的事实清单，优先于 v0.4 路线图。状态“已实现”指代码和本地验证，不等于完成生产环境验收。

## 产品定位

AgentTrust 是面向企业 Agent 的运行时安全与可信纠错控制平面，多租户 SaaS 为部署方向。客服退款是业务演示，不是一个已连接真实支付渠道的客服 SaaS。差异化是“检测失败 → 受限策略补丁 → 独立回归 → 真实流量灰度 → 人工标签与统计门禁 → 晋级/回滚”的可解释闭环，而不是让 LLM 自行修改生产代码。

当前适合：技术面试、作品集、内部 PoC、隔离环境试点。暂不适合：无运维接管地接入真实资金、承诺通用纠错准确率、直接向公网开放整套 Compose。

## 修复的关键安全问题

1. 生产首次初始化 Key 需要部署方 bootstrap token，不能让第一个匿名访问者直接接管；启动拒绝免认证/SQLite/关闭 RLS/共享迁移凭据/弱审计密钥的生产配置。
2. API 默认 `proj_demo` 也执行授权；JSON 中的 project_id 不能掩盖实际查询参数；不能把其他租户的项目挂到自己的工作空间。
3. 审批、回滚、能力租约签发和纠错标签要求 admin，客户端提供的 actor 被认证身份替换。
4. 原有“客户端提交成功率/误杀/耗时”不能作为发布依据；只接受服务端观察的 traffic_id 与人工期望动作。重复标签不增加样本数。
5. 回滚与晋级使用事务及版本比较，不能覆盖更晚的人工作业；并发重试不重复安装策略。
6. 模型地址必须匹配部署级完整地址白名单；平台模型 Key 不向租户任意配置的地址发送。HTTP 客户端关闭环境代理继承/重定向并限制响应体，出站继续检查 DNS/IP。
7. 异常轨迹、嵌套工具参数、审计负载不能直接落原始 Secrets；MCP 敏感参数拒绝透传，不静默修改已绑定租约的参数；A2A 消息/响应增加脱敏。
8. 修复多线程审计时间戳和链追加排序问题；签名锚点校验覆盖链头和计数，锚点及 Outbox 原子落库。
9. Temporal Activity 传递 workspace_id；新队列 `agenttrust-refunds-v2` 避免直接用新 payload 重放旧 Workflow。
10. 开发虚拟环境的 pip 24.0 审计发现已知漏洞，已升级 26.2.1；开发要求和 Docker 构建同步固定修复版。

## 自动纠错“准确”的证据边界

- 离线：30 条主回归 + 12 条 holdout，统计攻击召回、误杀、通过率与 Wilson 下界。不是随机划分出的真实客户独立样本，不能据此宣称通用准确率。
- 线上默认：10% candidate、至少 50 条人工标签、至少 50 条 candidate 请求、25 条 benign/10 条 attack 标签、持续至少 300 秒；FPR ≤ 2%、攻击召回 ≥ 95%、整体正确率 Wilson 95% 下界 ≥ 80%、错误率 ≤ 1%、P95 ≤ 5000ms。
- 其中“95%”是 Wilson 区间置信水平，不是承诺纠错准确率 95%。FPR/召回当前主要使用点估计，并未各自获得足够窄的区间。
- 人工标签不由模型自行生成，不接受前端编造延迟/错误率。采样记录的是候选/基线**策略决策**，不是完整模型回答质量或支付成功率。
- 当前指标窗口最多 5000 请求；paired block-rate change 是漂移观察值，不是已校准的漂移检验。标签/流量不足不晋级；生产直接 approve 不绕过门禁。
- 已上线版本继续检查错误率/延迟/已标注准确性，异常回滚；若存在更新策略，则拒绝旧版本回滚覆盖。开发默认即时自动发布只为演示，可关闭。

下一步准确性工作应先做租户级时间切分盲测、误杀申诉双人复核、样本功效计算、分业务/语言校准与顺序检验，再考虑模型微调。不要先给准确率承诺再寻找支撑样本。

## 验证记录

- 后端：32 passed；3 项 PostgreSQL 专用测试 skipped（本机未配置专用 PostgreSQL）。覆盖原有业务集成、并发退款、权限、生产配置 fail-closed、DLP、签名链、重试、线上误杀拒绝、SLO 回滚、重复晋级和 Phoenix SDK 合约。
- Ruff、Bandit、pip check：通过。
- pip-audit（已安装虚拟环境）、npm audit：修复 pip 后未发现已知漏洞。漏洞库结果只代表查询时已知风险，不等于安全证明。
- TypeScript 检查与 Vite 生产构建：通过。
- 浏览器：独立临时测试数据库启动同源控制台，验证数据加载、安全中心、资产同步与紧急停止。未修改用户原有业务数据库。
- CI 增加非超级用户真实 RLS/单连接池上下文清理/子表隔离测试，以及 Compose 配置与 API/PgBouncer 镜像构建。**本轮没有推送或运行远端 CI。**
- 未实测：真实支付、Docker 整栈启动、PostgreSQL RLS/PgBouncer 运行、恢复/PITR、Temporal 服务持久恢复、IdP 真实登录、Phoenix 远端实验、Webhook/S3 WORM、真实语义模型准确率。

## 参考开源/商业产品后，下一阶段优先级

以下为基于代码差距与公开文档的工程建议，不是产品安全认证，也不表示已复制了相应能力。

### 商用前优先补齐

1. **生产边界验收**：真实 RLS/连接池跨租户压测，认证数据与业务运行角色进一步分离；TLS/mTLS、出站代理、Secret Manager、恢复/PITR 演练及 RTO/RPO 证据。PostgreSQL 官方明确超级用户和 BYPASSRLS 可绕过 RLS，因此不能只以“已创建 policy”为验收。[PostgreSQL RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)、[PgBouncer 配置](https://www.pgbouncer.org/config)
2. **真正独立的审计信任域**：KMS 非对称签名、独立账号 WORM、VersionId/保留期回执与回读校验、自动投递/退避/死信/告警。当前只上传锚点，不是完整事件异地归档。S3 COMPLIANCE 保护具体对象版本，保留期内不可缩短，必须事先审定成本和保留期。[AWS Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html)
3. **身份与资金生命周期**：Key 撤销/轮换、OIDC 会话撤销、Step-up/MFA、SCIM、策略四眼审批；支付渠道幂等与对账补偿、金额 Decimal/整数分、超时运营台。现有 refund adapter 是模拟实现，不能给出真实支付 exactly-once 承诺。

### 建立竞争力

4. **按会话而非按 Prompt 防护**：服务器签发并绑定租户/主体的 session，统一 MCP/A2A/工具调用事件，跨步骤因果链和攻击轨迹回放。HiddenLayer 的公开运行时方案强调把多次调用重建成可回放会话；本项目目前只有时间窗阶段规则。[HiddenLayer Runtime](https://docs.hiddenlayer.ai/docs/products/runtime/overview)
5. **实装并校准检测模型**：接入真实 Prompt Guard 服务，DLP 引入 Presidio 的上下文/NER/校验混合识别，再以租户样本量化收益、误杀和延迟。LlamaFirewall 提供组合扫描器和轨迹扫描思路；Presidio 明确不保证识别全部敏感数据。当前只有接口，不能把上游基准结果用作本项目成绩。[LlamaFirewall](https://github.com/meta-llama/PurpleLlama/tree/main/LlamaFirewall)、[Presidio（原 microsoft 仓库已重定向）](https://github.com/data-privacy-stack/presidio)
6. **资产发现到可执行治理**：云/代码仓库/Agent 平台连接器，Owner、权限、最后观察时间、失效资产标记、多跳风险路径；联动策略模板、豁免到期和审批。Check Point/Lakera 文档区分配置风险与运行时保护，可用于校准产品信息架构，但其 Agent Security 文档标记为 early access，不应称为已全面成熟的 GA 对标。[Agent Security Overview](https://docs.lakera.ai/docs/agent-security)
7. **可复現评测平台**：独立标注集、时间切分、Prompt/策略/模型/数据版本谱系、实验去重、异步导出及 OTel Collector 分租户路由。Phoenix 的 Dataset/Experiment/Prompt 能力适合承载这些证据，不替代纠错发布门禁。[Phoenix Datasets](https://arize.com/docs/phoenix/learn/datasets-and-experiments/datasets-concepts)、[Phoenix Client](https://arize-phoenix.readthedocs.io/projects/client/index.html)

## 人工修改建议入口

建议优先确定三个取舍：首批客户是否涉及真实支付；检测数据是否允许离开租户环境；希望自动纠错优先减少漏报还是减少误杀。它们决定支付适配、模型部署、数据留存和发布门槛，比继续堆叠控制台模块更影响产品落地。
